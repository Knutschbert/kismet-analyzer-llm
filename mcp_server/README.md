# MCP server

This is a dependency-free, read-only MCP server for the semantic JSON output
generated by `kismet-analyzer`.

## Run

From the workspace root:

```bash
KISMET_LLM_DATA=output/generated/tree/TBL python -m mcp_server.server
```

On Windows, use:

```bat
scripts\run-mcp.bat
```

The default catalog is:

```text
output/generated/tree/TBL
```

Override it with `KISMET_LLM_DATA` when serving another game or generated tree.

## Performance and data location

The catalog cost is dominated by filesystem latency, not parsing. Measured on
the 52k-asset TBL tree (7,497 semantic docs):

| Data + index location | Index rebuild | `find_assets` | `get_asset_summary` |
| --- | --- | --- | --- |
| Windows drive over WSL 9p (`/mnt/p`) | ~8 s (threaded loads) | ~19 s/call | ~32 ms |
| WSL-native filesystem (ext4) | ~9 s | 70–116 ms cold, ~0.4 ms cached | ~0.4 ms |

The 9p numbers come from per-path `stat` round trips and SQLite journal I/O on
every query. **Keep the generated tree and its SQLite index on the native
filesystem**: sync the tree with `scripts/sync-tree-wsl.sh` (Windows drive →
`~/kismet-llm-data/`), then point `KISMET_LLM_DATA` at the copy.
`KISMET_LLM_DATA` accepts any path, so the same server configuration works for
either location. The remaining cold-scan cost is the `LIKE '%needle%'`
substring scan over the ~419 MB search text, sharded across 8 worker
processes with rowid ranges balanced by search-text bytes and pages read
through mmap; repeat queries are served from an LRU scan cache. The rebuild
loads docs through a chunked thread pool — measured single-threaded vs
threaded in `docs/performance.md` (9p: 25.9 s → 7.9 s).

The SQLite index is a derived cache (`.mcp-index.sqlite3` inside the data root
by default; override with `KISMET_MCP_INDEX`). It rebuilds automatically when
the manifest mtime or the index schema version changes — schema version 2 added
the precomputed lowercase `search` column that `find_assets` scans (one text
scan per call instead of re-concatenating every row's JSON per query, and no
separate `COUNT` rescan). Schema version 4 stores the search text flattened
(`name value` instead of raw JSON, ~20% fewer scanned bytes) and added the
byte-balanced process-pool scan, the scan cache, and mmap page reads. The
index roughly doubles in size to hold the lowercase search text. Schema
version 6 adds the exported-object index and a per-asset availability flag.

## Initial tools

- `find_assets` searches asset paths, classes, function names, property names,
  and default (CDO) value contents. Pass `includeDescendants: true` to expand
  every matched class's descendant subtree into the results (fuzzy class +
  subtree search, bounded by `maxNodes`).
- `get_lineage` returns one asset's class hierarchy: parent class, the full
  ancestry chain (terminating honestly at native classes or catalog
  boundaries), direct child classes, and class siblings. Accepts an asset path
  or a class name with or without the `_C` suffix.
- `get_asset_summary` returns concise asset metadata, function summaries, and
  (when present) the `defaultValues` and `exportedObjects` arrays.
- `list_exported_objects` lists placed actors, components, and instanced
  subobjects in one asset, with resolved classes and stable object paths.
- `get_exported_object` returns one exported object by path, with bounded
  properties.
- `find_exported_objects` searches the global exported-object index by class,
  name/path text, asset prefix, or property name/value. Use `classExact` for an
  indexed exact-class lookup; `className` is a substring scan and is slower.
- `get_function_summary` returns one function without CFG blocks by default;
  pass `includeBlocks: true` for bounded control-flow evidence.
- `find_references` searches indexed function-call and property references.
- `get_catalog_stats` reports indexed, semantic, function, and reference
  counts, plus `recentCalls` — the last 25 tool calls with durations, so call
  timings are visible without log capture. Each call also logs
  `tool <name> -> <ms>` to stderr at INFO (tune with `KISMET_MCP_LOG_LEVEL`).
- `refresh_catalog` refreshes the SQLite index after the generated tree changes.
- `get_call_graph` and `get_control_flow` return bounded execution evidence.
- `trace_behavior` locates candidate legacy behavior and follows its local graph.
- `compare_assets` compares functions and properties between related assets.
- `get_implementation_spec` turns one legacy function into an evidence-backed
  recipe for recreating it in a new actor.

All results are read-only and bounded. Empty assets remain discoverable through
the manifest but have no semantic output document. Hierarchy completeness is
bounded by the generated tree: children of a native class like `Actor` means
the indexed blueprints directly inheriting it, and two same-named blueprints in
different folders are indistinguishable by class name (the tool returns both).

## Default values (CDO)

Assets that have no Blueprint graph (for example utility AI behavior blueprints)
hold their meaningful data in the Class Default Object rather than kismet
bytecode. When the tree is generated with default values (`KISMET_LLM_DEFAULTS=1`
for `produce-llm.bat`, or `--defaults` on `gen-llm-tree`/`to-llm-json`), each
document gains a `defaultValues` array. Such assets become `parseStatus:
"complete"` and are indexed, so `find_assets` can locate them by a default value
and `get_asset_summary` returns those values. Schema version 2 also adds
`exportedObjects`, which retains each non-plumbing export's class and outer
chain for placed map actors and Blueprint components. Schema-version-1
documents have no such inventory; exported-object tools report it as Unknown
rather than as an empty result. `find_exported_objects` searches only documents
that actually carry `exportedObjects` and reports catalog coverage in its
response. See `docs/schema.md` for the field schema.

Index schema 7 omits verbose, low-value cooked metadata from the exported-object
`search` blob while keeping it in the detailed `properties` payload:
`StreamingTextureData`, `AlternateSkinWeights`, `PrecompiledEvaluationTemplate`,
`AggGeom`, `SplineCurves`, `CreationMethod`, `bNetAddressable`,
`UCSSerializationIndex`, `UCSModifiedProperties`, `StaticMeshComponent`, and
`BodyInstance`. Explicit `propertyName`/`propertyValue` searches still see them;
only global text search ignores them.

## Test

From the workspace root:

```bash
python3 -m unittest discover -s mcp_server -p 'test_*.py'
```

- `test_server.py` runs in-process unit tests against a synthesized catalog.
- `test_integration.py` launches the real stdio server and verifies the
  JSON-RPC lifecycle, tool results, and error handling against the static
  fixture catalog in `fixtures/tree/`.

The fixture catalog (a complete asset, a partial one, an empty one, and a
graph-less asset that carries only `defaultValues`) is git-tracked so tests stay
deterministic without the full generated tree. Tests write their SQLite index to
a temporary directory via `KISMET_MCP_INDEX`, keeping the fixture tree clean.
